# Запись проектного содержимого при общем допуске

Статус: частичный source-кандидат. Новый режим в dev не активирован. Human
content boundary квалифицирован отдельно; готовность машинных заданий и всего
совместимого cohort этим не подтверждается.

## Границы полномочий

Общий допуск открывает чтение через любое связанное пространство. Запись
требует пересечения **активных** подтверждённых пространств проекта с активными
пространствами исходного пользователя и прежних локальных полномочий:

| Ресурс / действие | Прежнее полномочие |
| --- | --- |
| Метаданные проекта и его участники | Владелец проекта |
| Задачи, доски, поля, компоненты, версии, комментарии, файлы, связи репозиториев | Владелец или существующее членство по действующему MVP-правилу |
| Подписка и голосование | Собственное действие читателя; голос за свою задачу запрещён |
| Создание связи задач | Изменение исходного проекта, чтение целевого |
| Удаление связи задач | Изменение исходного проекта |
| Очистка задачи из корзины | Изменение проекта удаляемой задачи, узкий контекст удаления её дочерних записей |

Сам по себе исторический is_system_admin не заменяет владельца или участника.
Пространство A в архиве не заимствует скрытое активное B. Пользователь с доступом
к активному B продолжает работу в A+B независимо от архивного legacy binding A.
Собственный архив проекта блокирует запись во всех его пространствах.

## Транзакционный контекст

GuardedDb получает серверный CentralRequestContext, созданный после fresh
Auth/SDK-проверки. Контекст содержит immutable identity, локальный user UUID,
исходный deadline, read/write service scope и подтверждённые пространства.
Тело HTTP не выбирает субъект, роль или настройки соединения.

Для write-request adapter открывает транзакцию и устанавливает SET LOCAL
контекст до SQL-операции. Все методы ConnectionTrait, включая returning query,
и явные TransactionTrait используют один механизм без разбора SQL-префиксов.
Обычные GET не получают write authority и остаются одним SQL-запросом.

SQL-guards повторно проверяют точное соответствие active local profile и
central_sub, действующую роль и актуальное состояние каталога. Порядок барьеров:
admission singleton, проекты в UUID-порядке, профиль/членство, каталог в порядке
публичных ID. Issue-to-project mapping перепроверяется после ожидания блокировки.
Прямой активный content SQL без серверного контекста отклоняется.

Исходный срок проверяется после ожиданий и отложенным constraint trigger при
commit. SET LOCAL не сохраняется в пуле. Ошибки PostgreSQL 42501 возвращают
Forbidden; 40001/40P01 — явный конфликт. Неизвестная мутация автоматически
не повторяется, неизвестная storage error не скрывается.

## Специализированные порты

M:N и Project lifecycle сохраняют собственные typed permits, текущую identity
под блокировкой и исходные deadline в receipts. Receipt не становится новым
допуском для последующего запроса. Создание проекта устанавливает точный непустой
набор связей до доски, в той же транзакции. default_board_id в исторической
схеме не имеет FK; нового понятия основного пространства не вводится.

tracker_begin_issue_purge сначала авторизует именно удаляемую задачу из корзины,
проверяет её актуальный проект и берёт блокировку. Локальный контекст разрешает
только удаление её дочерних записей/инцидентных связей. Он не разрешает чужую
обычную отписку, изменение соседней задачи, INSERT/UPDATE или новый job. Повторно
проверяются исходный субъект и deadline; валидные соседние записи сохраняются.

В compatibility-режиме write request также удерживает admission fence. После
owner-v2 adoption старый writer не должен обходить новую модель, даже если общий
flag ещё выключен. Adoption входит в согласованный cutover совместимого cohort,
а не в безвредный прогрев каталога.

## Проверки и оставшиеся границы

Native fixtures используют заполненную полную схему, настоящий PostgreSQL и
синтетический loopback Auth через реальный SDK verification path. Проверяются
активный B/архивный A и legacy binding, source-edit/target-read, отсутствие роли,
read-only PAT, foreign profile binding, атомарное создание, commit expiry,
возврат соединения в пул, архив/restore и узкое удаление с сохранением соседей.
Focused M:N fixture имеет действующий create context: отсутствие контекста
не может маскировать нарушение непустого набора и конкурентные удаления.

SDLC job/control и concrete artifact helpers требуют отдельных проверенных
machine grants и общего допуска исходного субъекта. Старый локальный grant или
read-only recipient/delegation proof не заменяет это полномочие. До интеграции
активные неклассифицированные SDLC content writes закрыты. Все machine read,
terminal/control, artifact и остальные consumer поверхности остаются открытым
cohort gate. Этот документ не разрешает активацию или откат на старые образы.
