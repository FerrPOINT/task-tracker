# Пространства проекта: пользовательские сценарии v2

Статус: согласованный объём реализации; runtime flag выключен до полного cohort.
Согласованный план не изменяет legacy Namespace UI до переключения cohort.

## Identity и кеш

Central subject берётся из проверенной SsoSession, не из локального UUID/email.
Локальный профиль Tracker сохраняет свой UUID. Identity хранится только в памяти;
logout/смена пользователя очищают её. Обновление токена того же человека сохраняет
формы; изменение подтверждённой роли или policy revision сбрасывает несовместимые
данные. Original validity скрывает каталог даже при зависшем refetch.
Истёкшее/неподтверждённое чтение не открывает legacy/operator fallback.

## Создание

Форма требует ключ, имя и один или несколько active admitted SpaceRef. Поиск и
страницы принадлежат серверу; выбор сохраняется между страницами. Нет первого,
основного или неявного пространства. Одинаковые названия различаются по ID.
Пустой каталог/ошибка/expiry не позволяют создать проект. Только POST v2;
lost response не повторяется автоматически и не считается успехом. Явный переход
к указанному ключу для проверки результата не создаёт ещё один проект.

Оба прежних entry points переключаются на общую RHF/Zod форму только под
VITE_SPACE_ACCESS_ENABLED. Ключ сохраняет published правило 1…10 латинских
букв/цифр/дефисов, включая одиночный дефис; UI не меняет регистр и не выбирает Space.
Подтверждённый POST201 закрывает журнал. Lookup — отдельный read существующего
проекта по исходному ключу: он не доказывает авторство создания. Открытие/использование
найденного проекта требует явного действия пользователя. Повтор остаётся тем же
POST/key; серверная уникальность ключа сохраняется. Отказ от повторов отдельно
предупреждает, что удаляется только session-журнал, а уже начавшееся создание
не откатывается. После смены identity/контекста поздний успех не запускает переход
и callback прежней формы. Повреждённый журнал сохраняется с themed recovery.

## Управление M:N

Настройки проекта показывают полный текущий набор по canonical GET v2 и CAS revision.
Видимые подписи берутся из общего каталога; для скрытого связанного пространства
показывается ID без запроса его Wiki/metadata. Неизвестная подпись, поиск и pagination
не удаляют связи. Добавлять можно только active admitted пространства. Последняя
связь не снимается. Сохранение требует прежней project-owner роли, write scope и
допуска к active пространству; сервер остаётся владельцем проверки полномочий.

Operation ID и полный исходный payload сохраняются до PUT. Потеря ответа оставляет
команду для повтора с тем же ID. Повтор возвращает реальный текущий набор, который
может уже отличаться после другой операции; UI не подставляет исходный requested set.
Конфликт требует явного чтения текущей ревизии и нового решения, без тихого merge.
Повреждённый журнал не удаляется автоматически. Archive не удаляет связи/данные.

## Общий выбор

Space и Project выбираются отдельно; SpaceRef в URL — registry_instance_id/space_id.
Старый namespace_id не угадывается и не становится первым project/space.
Wiki допускает Space без проекта. Шапка использует общий каталог, не legacy список
проектов. При смене контекста скрываются неподходящие данные.

## Проверки перед включением

Контрактные API tests; реальный QueryClient и Base controls; pending/empty/error/
expiry; одинаковые имена, несколько страниц, hidden retained link; actor switch и
late response; token refresh без потери формы; policy change; original-key replay/
conflict/неизвестный исход; обычный пользователь/администратор; IAB и screenshots.
Эта документация не объявляет ещё не реализованные UI сценарии проверенными.


## Источник состояния «только чтение»

Canonical GET связей сохраняет строгий ConfirmedProjectSpaces без новых полей.
Дополнительный response header x-pdlc-project-spaces-can-change — ограниченная
исходным окном UI-подсказка Tracker: текущий владелец проекта, write scope,
допущенное active пространство и отсутствие независимого архива проекта.
UI не вычисляет это полномочие из имени, admin-флага или выбранной страницы
каталога. Missing/invalid header означает несовместимый ответ, не разрешение.

PUT всегда заново проверяет условия под своими locks; header не принимается от
клиента и не является grant. После PUT/replay UI перечитывает текущую подсказку:
исторический receipt не выдаёт право изменения архивированного проекта.


## Неизвестный исход после потери права записи

GET /api/v2/projects/{project_key}/spaces/operations/{operation_id} читает только
собственную квитанцию исходного центрального автора при текущем project read.
Новый DTO ProjectSpaceOperationReceipt schema1 отделён от строгих прежних схем.
Он подтверждает commit канонического набора, возвращает исходный change и
applied_revision, сужает validity текущим исходным допуском. Это не grant и не
подтверждение Wiki. Источник — существующий атомарный operation/outbox receipt;
новая migration/перезапись истории не требуются.

Read PAT и архив проекта не мешают прочитать свою уже committed квитанцию.
Чужой автор/другой проект не открывают её. 404 означает отсутствие найденного
подтверждения, включая возможную ещё работающую транзакцию: исход остаётся
неизвестным, UI не создаёт новый ключ. При отзыве project read действует отказ.


## Первая версия допуска и окно запроса

Management GET возвращает x-pdlc-admission-policy-revision из того же
подтверждённого admission, что и links/read-only hint. Форма фиксирует baseline
до первого отображения контролов, не ожидая независимой страницы каталога.
Первая версия также очищает данные без известной версии; поздняя меньшая
ревизия не восстанавливает старый кеш. Missing/invalid header блокирует UI.

Если v2 запрашивается в staging до общей activation и повторная token
verification требуется отдельно, её validity и monotonic deadline сужаются
исходным request frame. Повторная проверка не создаёт новое окно для ответа.

## Каталог проектов и проверка маршрута

Шапка Tracker использует два отдельных Base SearchableSelect, без вывода проекта
из пространства. Общий Admin каталог читается через Tracker SDK relay. Переход
пространства ведёт в список, включая Space без проектов; ProjectRef выбирается
явно из серверного V2 каталога с отдельным поиском/страницами. Полный Tracker
instance ID сохраняется отдельно от локального Project UUID. Имена не ключи.

Список проектов использует server Space/q/count/page до pagination; sidebar и
header не вызывают legacy Namespace reader в новом режиме. Прямой project route
подтверждается exact project_key query внутри выбранного Space, без первого
поискового совпадения/автоматического перенаправления. Invalid/duplicate/legacy
URL context блокируется; explicit destination refs не переписываются.

Router-owned context epoch очищает прежние query data/drafts и закрывает queued
effects. Token refresh той же identity сохраняет context. Original expiry
скрывает protected route при unanswered revalidation. Глобальный /admin помечен
independent владельцем route и сохраняет собственные правила, включая outage
каталога. Это не даёт дополнительных API полномочий.

## Императивные операции и смена контекста

Под новым flag content mutations используют общий useScopedMutation поверх
TanStack Query. Каждый вызов сохраняет исходные identity/role/policy/context epochs
в private variables envelope; wire payload не меняется. Одна очистка QueryClient
не предотвращает поздний onSuccess, который снова запишет старые данные.
Проверка выполняется до RPC, после его исхода и перед callback; поздний ответ
прежнего пользователя/проекта/пространства не заселяет новый кеш и не открывает файл.
Автоматического повтора нет; unknown outcome остаётся у original-key протокола.
Это UI lifetime guard, не право сервера и не отмена уже начавшейся записи.

Login/register/logout сохраняют штатный identity lifecycle. Обновление токена
того же пользователя сохраняет допустимую операцию. Async callbacks, записывающие
private data после собственного await, также обязаны проверить исходный scope
непосредственно перед записью; wrapper не отменяет произвольный callback.

URL resource identity отличает проекты и задачи в одном Space; переход board →
backlog/settings того же проекта не создаёт новый проектный контекст.
Экспорт захватывает исходный project/format и проверяет scope перед скачиванием.
Единственный 401 refresh допускается для того же пользователя и действующего
контекста; ответ прежней identity не повторяется новым токеном.

Cross-product service switcher, оставшиеся legacy selectors, машинные/V3 и полная
серверная поверхность, включая read PAT export, требуют общей квалификации до
activation. Source tests не заменяют IAB и проверку поставленного cohort.
