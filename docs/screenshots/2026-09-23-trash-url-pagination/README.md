# Корзина проекта: URL-пагинация и адаптивная раскладка

Проверка выполнена 23.09.2026 в Chromium на production-сборке ветки с настоящими
Central Auth, shell и Task Tracker API. Для воспроизводимых двух страниц
подменялся только безопасный `GET /api/v1/projects/{key}/trash`; восстановление и
окончательное удаление задач не выполнялись.

## Воспроизведение

До исправления переход на вторую страницу менял только локальный `trashOffset`.
URL оставался без номера страницы, а reload возвращал первые 50 задач. При
произвольно большом offset пустые страницы откатывались по одной, создавая цепочку
запросов. На tablet пятиколоночная сетка включалась слишком рано и могла сжать
summary до нулевой ширины; destructive-текст на hover-фоне светлой темы имел
контраст 4.39:1.

## Результат

- `page=2` хранит страницу корзины и сохраняет соседние query-параметры.
- Прямая ссылка, reload, Back и Forward восстанавливают тот же список.
- Некорректный `page` удаляется через replace без потери других параметров.
- Пустая страница вне диапазона одним replace возвращается на первую; браузерный
  сценарий подтвердил ровно два offset: `49900 -> 0`.
- Карточная раскладка сохраняется до `lg`, поэтому tablet summary не схлопывается.
- Убрана ложная hover-подсветка некликабельной строки; destructive actions
  проходят WCAG AA по контрасту.
- Навигационные цели имеют высоту не меньше 44 px на mobile и 40 px на desktop.

Визуальная матрица: 2 страницы × 5 viewport (`375`, `768`, `1280`, `1920`,
`2560`) × 3 темы (`light`, `gray`, `dark`) = 30 состояний. Во всех состояниях
нет horizontal overflow, малых hit-area, безымянных контролов, неожиданных
вложенных скроллеров, серьёзных/критических Axe-нарушений и runtime/HTTP 5xx
ошибок.

Артефакты:

- `qa-report.json` — URL-flow, offset-переход и результаты 30 состояний;
- `page-1-*.png` — первая страница с полной таблицей/карточками;
- `page-2-*.png` — вторая страница и навигация.
