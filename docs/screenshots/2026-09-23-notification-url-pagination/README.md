# Уведомления: URL-фильтр и пагинация

Проверка выполнена 23.09.2026 в Chromium на production-сборке ветки с настоящими
Central Auth, shell, настройками уведомлений и Task Tracker API. Для
детерминированной второй страницы подменялся только безопасный
`GET /api/v1/notifications`; мутации уведомлений не выполнялись.

## Воспроизведение

До исправления переход на вторую страницу и выбор «Непрочитанные» меняли только
React state. URL оставался `/notifications`, поэтому reload, прямая ссылка и
Back/Forward возвращали первую страницу полного списка.

## Результат

- `filter=unread` хранит выбранный фильтр, а `page=2` — страницу списка.
- Соседние query-параметры сохраняются при фильтрации и пагинации.
- Back, Forward, reload и прямое открытие восстанавливают тот же список.
- Переключение фильтра сбрасывает страницу на первую и создаёт понятную запись
  browser history.
- Некорректные `filter` и `page` удаляются через replace без потери других
  параметров.
- Пустая поздняя страница одним replace возвращается к первой и не создаёт цикл
  истории или серию запросов для произвольно большого `page`.

Визуальная матрица: 2 состояния второй страницы × 5 viewport (`375`, `768`,
`1280`, `1920`, `2560`) × 3 темы (`light`, `gray`, `dark`) = 30 состояний. Во
всех состояниях нет horizontal overflow, малых hit-area внутри `main`,
безымянных контролов, неожиданных вложенных скроллеров, серьёзных/критических
Axe-нарушений и runtime/HTTP 5xx ошибок.

- `unread-page-2-*.png` — фильтр непрочитанных на второй странице.
