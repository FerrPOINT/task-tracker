# Backlog: URL-пагинация и размеры действий

Проверка выполнена 23.09.2026 в Chromium на production-сборке ветки с настоящими
Central Auth, shell и Task Tracker API. Для детерминированной страницы из 201
задачи подменялся только безопасный `GET /api/v1/projects/POLKA/backlog`; мутации
в компонентной матрице не выполнялись.

## Воспроизведение

До исправления переход на вторую страницу вызывал API с `offset=100`, но URL
оставался `/projects/POLKA/backlog`. Reload снова запрашивал `offset=0`, поэтому
пользователь терял страницу и не мог вернуться к ней через Back/Forward.

## Результат

- `offset=100` записывается в URL без потери `view=all` и восстанавливается при
  прямом открытии и reload.
- Back возвращает `offset=0`, Forward снова открывает `offset=100`.
- Некорректный `offset=-20` заменяется каноническим URL без `offset`, остальные
  query-параметры сохраняются.
- Кнопки создания, действий спринта, локального меню и пагинации, а также ссылка
  задачи имеют цель не меньше 40 px на mobile и desktop.
- Дублированное доступное имя ссылки создания задачи устранено.

Компонентная матрица: 5 viewport (`375`, `768`, `1280`, `1920`, `2560`) × 3 темы
(`light`, `gray`, `dark`) = 15 состояний. Во всех состояниях нет horizontal
overflow, малых целей внутри `main`, безымянных контролов, неожиданных вложенных
скроллеров, серьёзных/критических Axe-нарушений и runtime/HTTP 5xx ошибок.

Дополнительно на той же сборке прошли:

- `task-pages-live.spec.ts`: 12 маршрутов Task Tracker во всех предусмотренных
  темах и viewport;
- `functional-live.spec.ts`: 7 живых сценариев, включая Task Tracker
  project/issue/sprint/report, labels, links, attachments и worklogs; временные
  QA-сущности удалены тестом.
