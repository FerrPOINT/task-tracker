# Контекст создания и просмотра задачи в URL

Проверка выполнена 23.09.2026 в Chromium на production-сборке ветки с настоящими
Central Auth и Task Tracker API. Сценарий создавал два изолированных QA-проекта и
задачу, а затем удалял временные данные в `finally`.

## Воспроизведение

До исправления выбор другого проекта на странице создания не менял URL и после
reload возвращался первый проект. В карточке задачи выбор вкладки «Вложения» тоже
не отражался в URL, поэтому reload и прямые ссылки открывали «Активность».

## Результат

- `project_key` хранит выбранный проект без потери других query-параметров.
- `tab` хранит активную вкладку карточки; вкладка по умолчанию имеет канонический
  URL без лишнего параметра.
- Прямые ссылки, reload, Back и Forward восстанавливают проект и вкладку.
- Неизвестное значение `tab` удаляется из URL и безопасно открывает «Активность».
- Синхронные повторные события Radix Tabs дедуплицируются, поэтому один клик
  создаёт ровно одну запись browser history.

Визуальная матрица: 2 маршрута × 5 viewport (`375`, `768`, `1280`, `1920`,
`2560`) × 3 темы (`light`, `gray`, `dark`) = 30 состояний. Во всех состояниях
нет horizontal overflow, целей меньше 24 px внутри `main`, безымянных контролов,
неожиданных вложенных скроллеров, серьёзных/критических Axe-нарушений и
runtime/HTTP 5xx ошибок.

Дополнительно на той же сборке прошли:

- `task-pages-live.spec.ts`: защищённые маршруты Task Tracker по темам и viewport;
- `functional-live.spec.ts`: 7 живых сценариев, включая Task Tracker
  project/issue/sprint/report, labels, links, attachments и worklogs.

Артефакты:

- `qa-report.json` — URL-flow и машинно-читаемые результаты 30 состояний;
- `create-*.png` — форма создания на mobile, desktop и wide desktop;
- `detail-*.png` — карточка задачи на тех же контрольных конфигурациях.
