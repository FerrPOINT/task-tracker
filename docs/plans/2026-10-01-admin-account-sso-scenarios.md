# Оставшиеся SSO-сценарии Admin после Header

Расширенный живой прогон после Admin #29 выявил устаревшие selectors в
трёх соседних сценариях `sso-live.spec.ts`. Продуктовые auth/API не меняются.

- Проверять identity внутри открытого меню аккаунта, не в закрытой шапке.
- Выбирать «Выйти» как menuitem в первичном входе Admin, переходе к Task
  и managed-user сценарии установки пароля.
- Проверить весь SSO-файл непрерывно, без API mocks и Playwright retries;
  дополнительно четыре Admin live-теста на образах из слитого main.
- Сохранить проверки письма, одноразовости ссылки, центрального каталога,
  отключения собственной QA-учётки и сохранности PAT после общего выхода.

Тестовые пользователи имеют QA-префикс и штатно отключаются в finally;
credentials не публикуются. Изменения проходят lint/typecheck/docs validators.
Неизменённые frontend/backend проверены в этом же локальном acceptance run.
