# Декомпозиция: дизайн до интеграции

Статус: интерактивный design candidate, 2026-11-03. Утверждение дизайна ожидается.
План этапа согласован пользователем; это не утверждение ещё не показанного интерфейса.
Общий процесс: [Base PR 444](https://github.com/FerrPOINT/services-base/pull/444).

## Сценарий и навигация

В карточке одной задачи вкладка «Декомпозиция» находится перед SDLC.
Описание задачи и остальные вкладки сохраняются. URL хранит выбранную вкладку;
ссылка на раздел открывает его по стабильному ID. Раздел — часть плана без
собственного назначения, Workflow, чата, ветки или поставки.

Шапка плана: редакция, автор, требования и «Редактировать». Номер редакции
открывает прежние версии плана и причины изменений; отдельной кнопки «История»
нет. Вкладка «История» задачи предназначена для общей ленты событий.
Общая архитектурная часть и упорядоченные разделы, все свёрнуты по умолчанию.
Прямая ссылка раскрывает только указанный раздел, остальные остаются свёрнутыми. Каждый отвечает
на вопросы «Что сделать» (с ожидаемым результатом), «Как проверить» и
«Какие требования покрывает». По замечанию владельца убраны статусы выполнения,
счётчик N/M и действия отметки: декомпозиция описывает работу, а её фактическое
выполнение и независимая приёмка отражаются в существующем SDLC всей задачи.

Человек с правами задачи может редактировать план. При активном
изменяющем назначении или отсутствии права — только чтение с причиной.
В форме доступны добавление, удаление, перемещение вверх/вниз, явные Save/Cancel
и причина новой редакции. Черновик остаётся в памяти между вкладками; уход с него
требует решения пользователя. Смена сценария демонстрации подчиняется тому же guard.

Ошибка сохранения плана не очищает поля и позволяет повторить запись.
Редакции — просмотр снимков без восстановления; их разделы также свёрнуты
по умолчанию. При конфликте текущая редакция
и локальная правка видны раздельно; продолжение явно меняет базовую редакцию,
но ничего не сохраняет до повторного Save.

## Контракт владельца — ещё не реализован

| Будущая операция           | Требуемое поведение                                                                        |
| -------------------------- | ------------------------------------------------------------------------------------------ |
| Прочитать план и историю   | Доступ задачи, редакция требований, стабильные section IDs; история снимков                |
| Сохранить содержание плана | Ожидаемая редакция, причина, права/assignment guards, новая редакция с сохранением истории |

Названия URL, DTO и коды ошибок не вводятся этим preview. `model.ts` содержит
только типы вымышленных fixtures. Текущие OpenAPI, схема БД, API/CLI, agents и
production routes не меняются. После утверждения нужен отдельный owner-контракт
с unit и реальными PostgreSQL-проверками конкуренции/прав/сохранности.

## Изолированный предпросмотр

Из frontend: `pnpm design:decomposition:build`, затем `pnpm design:decomposition`.
Адрес: `http://127.0.0.1:4186/decomposition-preview.html?tab=decomposition`.
Существующие pinned tooling и Base UI; отдельный HTML/Vite entry без API proxy.
Данные вымышленные, все действия только в памяти. CSP запрещает сетевые соединения
и отправку форм; производственные auth/API clients и platform bridge не подключены.
Предпросмотр не входит в стандартный production build и не создаёт новый стенд.

Сценарии: нормальный план, пусто, один раздел, длинный текст, loading, read error,
readonly, active agent, conflict, stale requirements, save error, access revoked.
Смена сценария сбрасывает только демонстрационные данные. Светлая/серая/тёмная
темы используют Base. Реальные Task IDs, токены, публичные providers не нужны.

В conflict/save-error сценарии первая запись получает соответствующий ответ
в памяти; повтор проходит только после явного продолжения/исправления.
Предпросмотр не доказывает серверную авторизацию.

запросов, переполнения документа и недоступных действий.
