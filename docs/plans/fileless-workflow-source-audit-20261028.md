# Переход на общий CLI Workflow

## Поведение

Новые назначения PM принимают только `configured-cli-v1` с постоянной служебной
identity. Первое назначение владельцем может перевести ещё не начатую Draft-задачу
без маркера протокола. Forward-миграция 109 разрешает только этот переход:
нулевой owner CAS, отсутствие назначения, исполнения, опубликованных требований,
обсуждения требований и lifecycle. Исходная квитанция создания и входные данные
сохраняются. Повтор создания возвращает прежний результат и проверяет исходный хеш.
Начатые старые задачи этим переходом не охватываются.

Подтверждение точной редакции владельцем фиксирует маршрутизацию и исходный
репозиторий. Задача остаётся в Draft до принятия сохранённого результата Workflow
и наличия итогового комментария. Завершение PM переводит её в Backlog / Ready
без автоматического запуска Analyst. Это относится и к возврату на разбор PM.

## Перенос проверок

Подготовка сценариев candidates, Rework, source, Draft publication и critical PM
использует настоящий repository-путь нового протокола. Служебные identity и
ответы Workflow в этих тестах синтетические; живой приёмкой они не являются.
Проверки прав, CAS, повторов, rollback, закрепления источника и неизменности
первой публикации сохраняются. Native-доказательства технического исполнения
и его ресурсные ограничения остаются у существующего lifecycle.

Старый сценарий `sdlc_critical_pm_cycles_pg_tests` предполагал native resume PM
и автоматический переход обратно в Analysis. Этот исполняющий сценарий удалён.
Текущие проверки critical PM подтверждают вопросы, ответ владельца, новую редакцию,
сохранение первой истории, вторую генерацию маршрутизации, неизменность квитанций
и завершение в Backlog без нового Analysis intent. Применённые SQL-миграции
и исторические форматы не удаляются.

## Доказательства и оставшиеся проверки

- Scoped unit: 17 проверок configured CLI пройдены.
- Исходники API, infra, migration, CLI и тестовые targets компилируются.
- PostgreSQL-сценарии ещё не выполнены; требуется проверить forward-миграции
  на новой и заполненной копиях, включая переход существующей Draft-задачи.
- Технические fixtures необходимо проверить с постоянными identity всех ролей,
  сохранёнными результатами Workflow и итоговыми комментариями.
- Упаковка, полный согласованный прогон, PDLC1/Hermes, IAB, публикация и мерж
  остаются отдельными незавершёнными этапами.


## Удаление оставшегося native-планировщика PM

После переноса repository-потребителя у `prepare_critical_pm_completion` не
осталось production-вызовов. Удалены этот исполнитель, его Finalizing/Open
lease-контексты и выдача Analysis intent. Вход текущего чистого планировщика
содержит только серверное время наблюдения; реальные native-lease и terminal
технических профессий по-прежнему проверяют их владельцы.

Тесты native-finalization, lease renewal, prospective native receipt и native
scheduler completion удалены вместе с исполнителем. Вопросы, ответы владельца,
запрет старого согласия, подмена назначения, исходная история, ограничения CAS,
выделение receipt IDs и повторные поколения перенесены на configured identity.
Текущее завершение проверяет сохранённый Workflow result и заканчивает в
Backlog/Ready без Analyst; проверка поколений охватывает1,2,17.

Первая полная source-проверка обнаружила устаревшие API ожидания. Маршруты
bootstrap/lease больше не публикуются; текущие закрытые модели, авторизация и
исторические readback-форматы проверяются отдельно. Изменения тестов в старом
миграционном файле затрагивают только ожидание положения в расширенном списке:
SQL, up/down и порядок применённых миграций не менялись. Повторный текущий
source/PG/live gate ещё не завершён.
