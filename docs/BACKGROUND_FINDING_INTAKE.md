# Передача фоновой находки в Tracker

Поручение подготовки sdlc3 от 2026-11-09 включает реализацию человеческого
intake и установку согласованного комплекта после технических проверок.
Проверить реальные права, обязательные поля, Draft/Backlog, исходный ключ
операции и восстановление после потерянного ответа. Сохранённая задача остаётся
в Tracker, даже если Fleet ещё не сохранил связь. Агентские credentials не
разрешают этот intake. Автоматические исследования и включение расписаний
не входят в подготовку; живую приёмку проводить отдельно.

Статус: целевой контракт 2026-11-08; API и runtime ещё не заявлены готовыми.

В локальном кандидате от 2026-11-09 добавлены человеческие
`PUT/GET /api/v1/projects/{project_id}/sdlc/finding-intakes/{operation_id}`.
Запрос сохраняет точный материал Fleet, тип, редакцию, назначение и значения
полей проекта. Используются существующий immutable creation ledger и общий
нормализатор обязательных полей; обычное создание Draft сохраняет прежний hash.
Новая миграция `m20261109_0000116_background_finding_intake` ещё не установлена.

Для Backlog создаются настоящая задача, подтверждение человеком переданного
материала, source/routing snapshots и запись существующей очереди Analysis.
Источник `start_finding_analysis` отличается от PM completion. PM execution,
assignment и terminal не подделываются; business key выделяется существующей
общей sequence и закрепляется в creation ledger. Discovery проверяет этот
источник отдельно от завершения PM. Старые task-bound переходы сохраняются.

Техническая квалификация кандидата продолжается: PostgreSQL fixture уже
проверяет создание, обязательные поля, конкурентный replay, реальный discovery
очереди Analysis и отсутствие PM-записей. Целевой PG gate и all-target Clippy
кандидата с этим контрактом прошли; полная квалификация продолжается. До полного прохождения проверок и
Build/Apply наличие кода не означает готовность установленного intake.

При полной проверке обнаружена несовместимость прежнего SDK `ed61ec63` с
действующим CLI-контрактом opaque operation keys: encoded slash отвергался
до HTTP. `.base-revision` и `.namespace-base-revision` согласованы на точном
`a657f51fbbfd939ccf4343bdcf4f8cc83d262c9e`, уже используемом поставляемым
Tracker CLI. В нём сохранены traversal guards и поддержан такой сегмент пути.
Используемые backend-модули auth-core/shared/telemetry совпадают с прежним SDK;
остальные приложения не переключаются на этот pin. Проверки нового набора
зависимостей выполняются отдельно от прежних результатов.

Backlog использует обычный RequirementsDocument и validate_document. Его новые
checklist/prerequisite refs указывают на критерии и evidence точной редакции
находки; это идентификаторы дальнейших проверок, без записей об их выполнении.
Исходное evidence сохраняется полностью в dependencies. Значения обязательных
полей проекта предоставляет человек; они не заменяют evidence.

`GET /api/v1/background/projects/{project_id}/task-states?tasks=<UUIDs>` читает
только запрошенные задачи этого проекта после проверки человеческого доступа.
Для зарегистрированного Fleet backend есть отдельный internal reader с тем же
результатом и свежей проверкой полномочий владельца запуска. Агентам этот scope
не выдаётся. Возвращаются origin, project, database observed_at и не более100
различных IDs одного списка находок; содержимое чужих задач не раскрывается.
Для SDLC завершение всей задачи означает принятый Deployment result в Terminal,
Completed и освобождённое назначение; промежуточный Completed не подходит.
Для обычной задачи действует её статус is_closed. Fleet не перезаписывает более
новое наблюдение старым HTTP-ответом и отдельно показывает повтор проблемы.

Требования владельца интерфейса:
[Fleet — Фоновые задачи](https://github.com/FerrPOINT/fleet-control/blob/feat/background-tasks-20261108/docs/BACKGROUND_TASKS.md).

Фоновые процессы, расписания, находки и project-bound сессии принадлежат Fleet.
Workflow исполняет профессии без предварительной Tracker-задачи. Tracker не
создаёт Task для запуска поиска и не владеет отдельной очередью фонового анализа.

Человек выбирает точную редакцию находки и действие «В драфт» или «В бэклог».
Материал содержит название, описание, ожидаемый результат, критерии и evidence.
Поиск багов становится Bug, рефакторинг — Task. Цель Draft — дальнейшая работа PM,
цель Backlog — работа аналитика. Проверка прав и обязательных полей проекта
выполняется Tracker; членство в Fleet не выдаёт дополнительных полномочий.

Это новый источник создания задачи, а не фиктивное завершение PM и не обход
штатной модели требований. Нельзя подставить вымышленное owner confirmation,
Workflow terminal или изменить stage обычным generic patch. Реальный owner API
создания и маршрутизации требуется реализовать и проверить на точном кандидате.

Команда привязана к источнику Fleet, проекту, finding ID, редакции материала,
намерению Draft/Backlog и исходному ключу операции. Проверяется актуальный
человеческий доступ. Точный replay возвращает прежнюю задачу; конфликт материала
не создаёт новую. Unknown outcome читается по исходной операции. Нельзя требовать
одной транзакции между БД Fleet и Tracker: сохранённая задача остаётся в Tracker,
а её связь и результат доставки восстанавливаются во Fleet.

Недостающие обязательные поля показываются человеку в интерфейсе находки.
Они не заполняются вымышленными значениями; частичная передача не объявляется
успехом. До успешного создания материал остаётся находкой.

«Не делаем» с обязательным комментарием хранит Fleet и учитывают фоновые агенты.
Они не отменяют решение и не редактируют Tracker-задачи. Повторное обнаружение
дополняет ту же находку. Незавершённая связанная задача не порождает дубль;
возврат проблемы после завершённой позволяет человеку создать новую связанную
задачу с новым намерением, сохраняя прежние IDs и историю.

Прежние незавершённые Bug Search intake/авторегистрация/автоисправление/специальная
verification заменены этой моделью. Обычный SDLC созданной человеком задачи,
применённые миграции и исторические receipts сохраняются. Ни документация,
ни будущая source-реализация не означают включение расписания или rollout.
